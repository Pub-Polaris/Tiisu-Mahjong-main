# 七子麻将 · Tiisu Mahjong

七子麻将（Tiisu Mahjong／七子麻雀／Nanako Mahjong）是在国标麻将、立直麻将与川麻的基础上，融合大量自创役种与规则改良而形成的一种独立新规麻将。

它并非简单地混合既有规则，而是以“7赋起和”为基点，重新梳理了手牌价值的计算方式——用“赋”作为统一的计量单位，将番数逻辑替换为赋数累加，并在关键阈值上设置固定的点数锚点以方便快速进行基数性的计算。

该规则保留了立直麻将的防守意识，舍弃了立直麻将较为令人诟病的“役欲症”（役种过少）与“宝牌滥赏”（断幺13dora）等问题，吸收了国标麻将的役种多样性，也引入了川麻中某些快速听牌与进攻节奏的处理方式与特殊奖励/惩罚，鼓励玩家适时根据场况选择鸣牌/报和进攻或默听防守，同时去掉了赤宝牌、四季牌等元素，使牌组回归136张的基础构成，简化理解难度。

其核心设计是被称为“赋”的基本点数单位。在此基础上每一手牌的得分构成更加透明可溯：用户可以通过逐项累加赋数，清楚地知道自己的点数来自哪些役种、哪些附加条件，而非依赖模糊的“番数×符数”或较为复杂的公式换算与点数上下舍/入。您只需要简单的加减乘除与确定手牌是否位于特定锚点上或下（7、14、21、28赋）即可快速算出当前手牌点数。

七子麻将亦引入了大量原创役种，（如“小于七／大于七”“水中月”“镜中花”“南北通”等），并设置了专属的高得点体系，在一定程度上将七对以及其7个对子Blocks视为了“标准形”与合法面子而非常规麻将中的特殊形，并赋予了七对直接的起和赋数（7赋），牌局中的特殊牌型亦有明确的独立定位，以鼓励用户在七对时避免放弃手牌而进行对牌面的效益改良。同时传承役满（如国士无双、四喜和、大三元等）以“民工役满”的形式保留，确保经典役种不被边缘化，但通过复合限制和特例加记分数规则，将其纳入赋本位体系中进行统一管理，对阐释“和牌状态”的“美学”具有鼓励与研究作用。

本规则适合对新式或特殊的麻将计分逻辑有探究兴趣、希望摆脱固定番种、计分规则框架、或者对于其他麻将规则有了解，想寻找在其他麻将规则之外的新鲜策略、与扩展思考维度的用户。

其允许不限制规则微调与役种变更，经过您的自定义后可被用作友人之间的娱乐对局规则，也一定程度上具备作为独立或创新比赛规则的理论框架与探索基础。

## 关于 AI / 写在前面的话

先说清楚一件事，免得误会：**规则是我的，代码不是。**

七子麻将这套规则（役种、赋的算法、点数锚点、赐马、跳墩……）从头到尾是我自己想的、自己定的、自己一条条抠出来的。我不会写代码，但我会写规则，好歹这两件事我一直分得挺开的 ~~（废话，不分开点我头更炸）~~。

代码这边，是 AI 帮着一起搭起来的。我在用 opencode 和 DeepSeek Harness 这两个工具，跟它们来回磨：我出规则、出判断，它们出实现、出文档。所以这个仓库里的代码，基本是“我说要什么 + AI 把它写出来”的产物。

对于人类来说（能从浏览器页面上看到这玩意儿的你、我）只需要记住这些玩意儿：

- **规则书是权威**。代码和规则书对不上的时候，以规则书为准，代码一般是错的。（除非AI自己改过规则书且没有对上，请写issues，~~我会大棒胡萝卜去撵大肥鱼的~~）
- **AI 会犯错**。要求一个规则它实现跑偏、或者把某条口径理解歪了，这都发生过，而且不止一次（我都很烦我自己为什么前几年大学，大一下半学年的时候，没有去转专业到编程）。现在总算有了一套自动断言兜底（`scripts/run_all.py`：役种/赋/点数 + 引擎规则 + 运行态隔离 + 全自动冒烟），但它只验“跑没跑通”和已经写死的用例，盖不满所有规则——所以你如果玩到不对劲的地方，**大概率**是真有问题，**不是**你的错觉。
- **这个项目和我一样，还在成长**。规则里有些条目我自己都还在纠结（文档里标着“待确认”的那些），实现上也还有没补完的缺口（缺口清单在 `docs/` 里，我写得很直白，包括“这条我故意不补”，当然这一个括号里除了这句话之前都是AI写的）。

如果你发现问题、或者觉得某条规则该是另一种判法，欢迎提。**规则的最终解释权在我这儿**，但被指出漏洞我也基本就算是一点都不介意——这项目能到现在，就是靠一轮轮“这里不对”的**AI一边写，人类一边开游戏大调查**出来的。

最后一句：这不是个要拿去比赛、或者证明AI能力在一步步进步的东西，它先是“我想玩的一种麻将”，然后才是一个程序。我一直相信玩得开心（哪怕是Vibe Coding到死）是人类最最重要的东西，也希望各位能在这个仓库里找到你所感兴趣的东西。
