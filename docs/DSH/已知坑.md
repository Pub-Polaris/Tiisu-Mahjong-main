## 一、启动与加载

### 1.1 偶发 `WinChecker is not defined` / `TiisuMahjong is not defined`
- **现象**：页面加载后不渲染（`#wallCount=0`、四座位无手牌、无 JS 报错），日志出现 `[boot] 依赖未就绪`；重开有时又好了。
- **原因**：三件事叠加——
  ① `index.html` 的启动兜底用 `setTimeout` 轮询（30×100ms），**依赖未就绪时永久放弃启动**；
  ② 在无头 `--virtual-time-budget`（虚拟时钟）下 `setTimeout` **瞬间触发**，实际没有等待网络；
  ③ `server.py` 原为**单线程** `HTTPServer`，页面并发请求 8 个脚本 + 3 个 API 时会排队/超时。
- **处理**（均已修复，2026-09-26 追加）：
  - `index.html` 改为 `ensureDeps()`：`window.load` 后逐项检查全局是否就绪，缺失则**动态补加载对应 `src/*.js`**（`<script onload>` 等真实网络，带 `?reboot=` 防缓存），全部就绪才装配。
  - `server.py` 的 `DualStackServer` 改为 `ThreadingHTTPServer`（`daemon_threads = True`）。
  - 仍**务必确保只有一个 python 进程**（见根 `AGENTS.md` 2.2 / 六.5）。
- 状态：已修复。

### 1.2 全自动模式（`?auto=1`）需要足够虚拟时间
- **现象**：抓取时页面还没有和牌/流局结果。
- **原因**：四家 AI 走完整局需要时间。
- **处理**：`--virtual-time-budget` 给到 90000–180000。

### 1.3 `?auto=1` 下没有可点击手牌是正常的
- **现象**：抓 `class="tile clickable"` 为 0，误以为渲染坏了。
- **原因**：全自动时四家都是 AI，人类座位不存在。
- **处理**：验人工模式用 `?mode=4`（应有 14 个 clickable）。状态：注意事项。

### 1.4 直接对 `--dump-dom` 结果做子串计数会误判（工具坑）
- **现象**：明明页面没渲染手牌，却数出 `class="tile clickable"` ≥ 1。
- **原因**：`--dump-dom` 输出的是**完整 HTML 序列化结果，包含内联 `<script>` 的源码文本**；`renderSeat` 的模板字符串里就写着 `class="tile clickable"`，于是子串计数把"源码"当成"已渲染 DOM"。
- **处理**：计数前先剥离 `<script>...</script>` 与 `<style>...</style>`（`scripts/smoke.ps1` 的 `Get-DomText` 已这么做）。状态：注意事项（工具层）。

### 1.5 无头页面里 `confirm()` 会阻塞
- **现象**：若进入含 `confirm(...)` 的分支，页面停在确认框处不再推进（dump 出来就是"只渲染了初始空桌"）。
- **原因**：`maybeResume()` 在检测到未完成存档时会 `confirm`；无头环境无人工点击。
- **处理**：演示/自测模式（`?auto=1`、`?scoretest=1`）已在代码中**跳过恢复确认**；做其它无头验证时也要注意别落到该分支。状态：注意事项。

## 二、规则与判役

### 2.1 副露被并入暗手重新拆分 → 结构性误和
- **现象**：暗手不成形却能"和牌"（历史牌例：暗手 `349m` 荣和 `1m`，副露 `234m/8888m/456m`）。
- **原因**：`checkWin` 收到"暗手+副露"全并后整体拆分，副露被当可变面子。
- **处理**：已改为"暗手单独拆 + 副露作固定面子"。**新增役判定时不要假设 `hand` 含副露**（`conditionFn` 的 `hand` 才是全手）。状态：已修复（P08）。

### 2.2 明杠后少一张、和不了牌
- **现象**：开明杠后手牌张数不对，自摸判定恒 `not_formed`。
- **原因**：`applyMeld` 的明杠分支只移除 3 张、未从岭上补摸；且回合状态用固定 13/14 判断。
- **处理**：明杠后补摸 1 张岭上；手牌物理张数用 `totalTiles() === 13/14 + kongCount()`。状态：已修复（P09）。

### 2.3 混全带幺判反 / 七对子误判 / 风牌役牌过宽
- **现象**：混全带幺该中不中；同种 4 张被当两对（七对）；任意风刻都算役牌。
- **原因**：判定写法错误 / 未区分 7 种各 2 张 / 未限定圈风+门风。
- **处理**：混全带幺改为"每面子至少含一幺九或字"；七对子要求 7 种各 2 张且不叠刻子役；风牌役牌仅算圈风+门风（需传入 `seatWind`/`roundWind`）。状态：已修复。

### 2.4 卡七误判
- **现象**：调试模式下，末张是 7 就被算卡七加成。
- **原因**：`hasKachi7` 在 `winTile` 为空时回退到 `hand[last]`。
- **处理**：只依据和牌张 `winTile`。状态：已修复（P05）。

### 2.5 门风不随庄家变化
- **现象**：换庄后各家风位标识不变，役牌判定错。
- **原因**：此前用 `handsPlayed/4` 推算场风、门风固定写死。
- **处理**：`updateSeatWinds()` 按庄家位置 + 场风动态分配；`advanceDealer()` 绕回起点时场风 +1。状态：已修复。

### 2.6 南北通偏松 / 水中月与指南不一致（有意不补）
- **现象**：南北通未校验南北风组成面子/雀头。
- **处理**：**有意保持现状**（见 `规则缺口清单.md`）。若要收紧，需北极星确认。状态：有意不补。

## 三、对局与状态

### 3.1 牌山恒为 79（不随骰子变化）
- **原因**：旧模型四侧各 33 张 + 尾部 4 张岭上，固定不变。
- **处理**：改为跳墩模型，活牌山 = `136 − 2S`；配牌后 = `136 − 2S − 53`。状态：已修复。

### 3.2 终局被重复结算 / "下一局"点了没反应
- **原因**：`advanceRound()` 可被重复调用；终局后逻辑未定义。
- **处理**：`advanceRound()` 加终局防重；终局后再点"下一局" = 重开新比赛（`resetAll` + `startMode`）。状态：已修复。

### 3.3 存档 `inProgress` 不准
- **原因**：在 `handsPlayed` 更新前就存档。
- **处理**：`saveSessionState()` 移到 `advanceRound()` 之后。状态：已修复。

### 3.4 多家荣和重复累加局数
- **原因**：每个胜者各 `reportStats({rounds:1})`。
- **处理**：`rounds` 只在 `advanceRound()` 记一次；`wins/daxingqi` 按胜者记。状态：已修复。

### 3.5 调试台命令不生效 / 设置无效
- **现象**：勾了"记录牌型"但没记录；`debug.html` 发了命令没反应。
- **原因**：`recordTiles` 只勾了界面未真正赋值；`POST /api/state` 曾返回空 body 导致前端 `.json()` 抛错。
- **处理**：启动时真正置 `game.recordTiles`；`POST /api/state` 回写 JSON。状态：已修复。

## 四、界面渲染

### 4.1 吃牌按钮消失
- **原因**：用 `outerHTML` 整体替换容器，销毁了后续要引用的带 id 元素。
- **处理**：行动区改由 `renderActionArea()` 统一生成（读引擎 `_actOpts` 状态），不再整体替换。**不要再用 `outerHTML` 重建这些容器。** 状态：已修复。

### 4.2 流局按钮出现两个
- **原因**：底部工具条与手牌上方各有一个。
- **处理**：只保留手牌上方（`#seatActions` 内），底部 `#flowBtn` 已删。状态：已修复。

### 4.3 和牌计分面板空白
- **原因**：`showMsg` 需要渲染 HTML（表格），若按纯文本处理会失效。
- **处理**：`showMsg` 用 `innerHTML`；计分内容由 `buildWinOverlay` / `buildMultiWinOverlay` 生成。状态：已修复。

### 4.4 换肤时改错"结构类"
- **注意**：`.action-bar` / `#actionBar` / `#seatControls` / `#flowBtn` 等**已不存在**。现用 `.seat-actions` / `#seatActions`。改布局前先看 `docs/北极星_(人类)/design_design_guide.md` 第三节的最新 id/类表。状态：注意事项。

## 五、服务端与文件

### 5.1 两个 server 争 7777
- **现象**：间歇性脚本加载失败、页面半渲染。
- **处理**：启动前先杀干净 python；`netstat` 确认只有一个 LISTENING。状态：注意事项。

### 5.2 单线程服务在高并发下排队（已修复）
- **现象**：页面偶发某个 `src/*.js` 加载失败，报 `[boot] 依赖未就绪`。
- **原因**：`DualStackServer` 原继承单线程 `http.server.HTTPServer`；页面一次并发请求 8 个脚本 + 3 个 API，排队期间可能超时。
- **处理**：改为 `http.server.ThreadingHTTPServer`（`daemon_threads = True`）。状态：已修复（2026-09-26 追加）。

### 5.3 日志写错位置
- **注意**：`/api/log` 现写 `logs/output.txt`（早期写根目录 `output.txt`）。找日志别再看根目录。状态：已修复。

### 5.4 归档误删
- **注意**：服务端启动时会把**上一会话目录**压成 `logs/archive_*.tar.gz` 并删除原目录；只归档形如 `YYYYMMDD_...` 的会话目录，保留 `archive_*` 与 `*_chr_console.log`。状态：注意事项。

### 5.5 读取默认设置被污染
- **原因**：`DEFAULT_SETTINGS.copy()` 是浅拷贝，`optionalYaku` 列表会被共享。
- **处理**：改用 `json.loads(json.dumps(...))` 深拷贝。状态：已修复。

## 六、工具与环境

### 6.1 PowerShell 不支持 `&&`
- **处理**：用 `;` 顺序执行，或 `cmd1; if ($?) { cmd2 }`。状态：注意事项。

### 6.2 内联 python 带引号容易被 PowerShell 吃掉
- **现象**：`python -c "..."` 里的引号/正则被 shell 解析，报 `SyntaxError` 或 PowerShell 报缺 `]`。
- **处理**：把脚本**写成 `.py` 文件**再 `python -X utf8 file.py`（最稳）。状态：注意事项。

### 6.3 本机没有 Node.js
- **注意**：不要用 `node --check` 验语法；运行 `scripts/smoke.ps1`（内含 `scripts/syntax_probe.html`），或按根 `AGENTS.md` 2.4 手工抓页。状态：注意事项。

### 6.4 临时探针文件残留
- **注意**：历史上有 `probe_*.html` 被误打进对外发包（`TiisuMJ_Public_Test_20260911.zip` 内仍含 `probe_seatwind.html`）。**探针用完即删**；对外发包前检查 zip 内容。状态：注意事项。

### 6.5 嵌套 / 反复从网络盘跑 PowerShell 会触发 AMSI 崩溃（新）
- **现象**：用一个 `.ps1` 或 `.cmd` 串联调用其它 `.ps1` 时，偶尔整个进程崩掉，报
  `System.AccessViolationException: 尝试读取或写入受保护的内存…`，调用栈里是
  `AmsiUtils.AmsiNativeMethods.AmsiScanBuffer`。退出码 `-1073741819`（0xC0000005）。
- **原因**：Windows **AMSI**（反恶意软件扫描接口）在 Powershell 解析来自网络共享（`\\<NAS>\...`）的脚本内容时崩溃；与脚本本身无关（单独运行同一脚本通常正常）。
- **处理**：一键校验改用 **Python**：`scripts/run_all.py`（另有 `run_all.cmd` 仅作为薄包装）。**不要**在 PowerShell 里 `& powershell -File ...` 嵌套串联断言脚本。状态：已规避（`run_all.py`）。

### 6.6 `class` 声明在经典脚本里不挂 `window`（新）
- **现象**：跨 iframe 访问 `w.TiisuPlayer` / `w.TiisuMahjong` 得到 `undefined`（`Cannot read properties of undefined (reading 'prototype')`）。
- **原因**：`class X {}` 在经典脚本中创建的是**词法全局绑定**，不是 `window.X` 属性（`function X(){}` 才会挂）。
- **处理**：测试里用 `Object.getPrototypeOf(实例)` 反查原型（见 `scripts/engine_test.html`）。状态：注意事项。

### 6.7 Python 输出到 GBK 控制台会抛 UnicodeEncodeError（新）
- **现象**：脚本跑完却在打印结果时崩：`'gbk' codec can't encode character '\u2212'`（测试名里的 `−` U+2212）。
- **处理**：脚本开头 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`（`run_all.py` 已加）。状态：已规避。
