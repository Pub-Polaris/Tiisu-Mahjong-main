## 一、项目是什么

一个**自创规则的四人麻将**实现：自有役种体系与"赋本位"点数表，包含赐马、跳墩、门风等非标准机制。纯前端（HTML/CSS/JS）+ 一个 Python 静态服务（日志/设置/存档/统计），无构建链、无数据库、无网络依赖。

作者：北极星（规则与产品意图的唯一来源）。代码与文档由 AI agent 实现。

## 三、关键不变量（别改坏）

1. **`checkWin` 收暗手，副露是固定面子**。`WinChecker.checkWin(hand, ...)` 的 `hand` 只含暗手，`melds` 作为固定面子传入，结构判定为「暗手拆成 (4 − meldCount) 组面子 + 1 对」。**不要**把副露并回暗手再拆（这是历史 P08 的根因）。
2. **起和门槛 7 赋**，且**赐马赋不计入起和**（先判和，再叠加赐马赋查表）。
3. **赋→点查表**：`0–6: 700·f`；`7–13: 7000+700(f−7)`；`14–20: 14000+700(f−14)`；`21–27: 28000+700(f−21)`；`≥28: 35000`。庄家 ×1.5；自摸三家均摊、余数归自摸者。
4. **牌山跳墩模型**：骰子和 S → 跳墩 `2S`（含 4 张岭上 + 王堆 `2S−4`）不参与普通摸牌；活牌山 = `136 − 2S`。
5. **计数分口径**：`handsPlayed` 每手 +1（含连庄）；`dealerCount` 仅在庄家换人时 +1（决定"东N局"的 N）；`roundWindIdx` 决定场风（绕回起点时 +1）。
6. **局数只记一次**：`advanceRound()` 里 `reportRound()`；和牌/大七星按胜者 `reportStats()`。
7. **三块状态互不混用**：设置 / 存档 / 统计分别落 `settings.json` / `state.json` / `stats.json`。

## 四、状态文件三者（别搞混）

| 文件 | 谁写 | 内容 | 何时读 |
|---|---|---|---|
| `settings.json` | 门户 `portal.html`、调试台 `debug.html` | `thinkSeconds` / `optionalYaku[]` / `showMa` / `daxingqi` / `showDebug` / `showWallViewer` / `recordTiles` | 游戏页启动时 |
| `state.json` | 游戏页 `engine.js` | 会话存档（`playerUUID`/`modeTarget`/`handsPlayed`/`handNumber`/`scores`/`dealerIndex`/`honba`/`roundWindIdx`/`dealerCount`/`inProgress`）+ 运行时命令 `game_cmd` | 游戏页启动时（提示恢复）；每秒轮询命令 |
| `stats.json` | 游戏页 | 累计 `daxingqiCount`/`wins`/`rounds`/`byPlayer` | 门户统计区 |

**运行时命令机制**：`debug.html` 或键盘快捷键写入 `state.game_cmd`；游戏页每秒轮询 `/api/state`，发现后执行并回写 `game_cmd: null`（不落盘为设置）。

可用 action：`next`（下一局；终局后 = 重开新比赛）/ `auto`（切换全自动）/ `reset`（整场重置）/ `flow`（九种九牌流局）/ `setHand`（手牌调试）/ `speed` / `optional`（切换可选役）/ `record` / `render`。

> 注：`internalScore`（内分）已于 260822 移除，**不再是可用 action**。

## 七、下一步建议（优先级）

1. **最小自动化回归**（最高）：一个脚本跑 N 局全自动，断言"无报错 / 局数达标 / 分数守恒 / 无异常 `not_formed` 刷屏"。当前项目最大风险是"没有机器在替人盯正确性"。
2. **影响手感的流局规则**：流局本场 +1、未听惩罚、三家和牌流局。
3. **拆分 `index.html` 的渲染层**（若继续增长）。
4. **美术换肤**：随时可插队，不影响正确性（见 `docs/北极星_(人类)/design_design_guide.md`）。
5. **双役满 70000**：需动 `calcPoints` 结构 + 一批役，放在规则稳定后再做。
