## 一、你能直接改、不需要实现方的部分

### 1.1 牌面 SVG（`mj_tiles/`）

游戏里所有牌都是 `<div>` 的 `background-image` 指向这些文件：

| 资产 | 数量 | 说明 |
|---|---|---|
| `{1-9}m.svg` 万子 | 9 | 建议透明或象牙底 |
| `{1-9}p.svg` 饼子 | 9 | 同上 |
| `{1-9}s.svg` 索子 | 9 | 同上 |
| `{1-7}z.svg` 字牌 | 7 | 东南西北白发中（1z东 2z南 3z西 4z北 5z白 6z发 7z中） |
| 牌背 / 空白 | 未建 | 暗牌/弃牌背面当前用纯 CSS 色块（`#2A4A6A`）；如要统一牌背图案，建 `mj_tiles/back.svg`，由实现方挂上 |

**尺寸约定**：SVG 画布建议 `width=19 height=26`（逻辑单位，可缩放），当前已有象牙白底 `<rect fill="#F6F1E3">`。只需保证四角圆角与牌面元素布局合理。

### 1.2 骰子

当前骰子用 emoji 🎲 + 文字（如「🎲 定庄: 3+5=8 → 东家坐庄」）。如要真骰子图，建 `mj_tiles/dice1.svg ~ dice6.svg`，由实现方替换。

### 1.3 文本 / 中文标签

`index.html`、`portal.html`、`debug.html` 里的中文（庄/东/南/西/北/流局/赐马…）都可直接改文案，或交实现方改。

## 四、交付方式与配合约定

### 方式 A：美术发成品（SVG/PNG/配色/字体名）
实现方**逐项提问，一次一组，不轰炸**：
1. 牌面：`mj_tiles/*.svg` 直接替换？牌背要不要？
2. 桌面：背景沿用 CSS 渐变，还是给整图（给 `.table` 挂 `background-image`）？
3. 中央河/座位/按钮：位置大小是否要改？旋转方向（左/右座 90°）？
4. 颜色：是否收敛成 CSS 变量换主题？给主色/辅色/强调色。
5. 字体：中文用什么字体族？

### 方式 B：美术交"仅布局占位页"
把 HTML/CSS（或标注图）交实现方，按**坐标/尺寸/层级**映射回 `index.html`：
- 先确认：占位页是"最终视觉"还是"示意结构"？
- 逐区块确认：这个块 = 哪个 id？宽高比？z 层级（是否压住手牌）？
- 确认后再改 CSS，不破坏逻辑。

## 五、画布规格与安全区

- 桌面画布：`1460 × 900`（逻辑像素，圆角方桌，可缩放）。
- 左上信息栏（约 230×220）与中央方形（580×380）为常驻功能块，可融入背景风格，但**不要覆盖四座位手牌区**。
- 四座位手牌区宽度：下座约 1100、上座约 660、左右座约 280（竖排旋转 90°）。
- 底部 `.runtime-bar` 与 `.debug-log` 属页面级元素，不属于桌面。

## 六、改动流程约定

1. 美术给资产 → 实现方提问（方式 A 的 5 组）→ 落地 → 浏览器 F12 预览 → 反馈 → 迭代。
2. 美术只交付**资产文件**（SVG/图/色值/字体名），不交付代码。
3. 实现方负责把资产挂进 DOM/CSS，并保持所有对局逻辑（判役/计分/回合/日志）不变。
4. 每次换肤改动记入 `docs/OpencodeAgent_老Agent想说的话/CHANGELOG.md`。
