## 一、一句话总览

这个游戏 = **一个网页（HTML 画界面）+ 几个 JS 文件（管逻辑）+ 一个 Python 小程序（管存盘/日志）**。

```
你点开网页 → 网页加载 JS → JS 生成牌山、发牌、走回合、判和牌 → 每一步和最终结果写进磁盘日志
```

没有联网、没有数据库，全部在本机跑。

## 三、src/ 里每个文件是干嘛的

一张牌在代码里就是一个对象：`{suit:'m', num:5, id:'m5'}`（花色 m/p/s/z + 数字）。

1. **`tiles.js` —— 牌本身**
   造 136 张牌、洗牌、排序、把 `"123m456p"` 这种字符串解析成牌。谁都不依赖它，它被所有人用。

2. **`winchecker.js` —— 判役（核心）**
   回答："这一手牌和没和？几分？有哪些役？"
   里面 `checkWin()` 是全游戏最重要的函数。改役种规则就改这里。

3. **`aiPlayer.js` —— AI 出牌**
   回答："AI 该打哪张？" 策略是"尽量凑顺子/刻子、留对子、先扔孤张字牌"。

4. **`engine.js` —— 对局引擎（最大）**
   整个"一局怎么打"都在这里：发牌、谁摸谁出、吃碰杠、和牌结算、流局、连庄、分数、赐马、门风。
   `TiisuPlayer`（一个玩家）+ `TiisuMahjong`（整局状态机）。

5. **`tenpai.js` —— 听牌判定**
   流局时挨个试 34 种牌，看打哪张能听。

6. **`notation.js` —— 把牌变成文字**
   把牌写成 `"123m456p789s1122z"` 这种记号，方便写日志。

7. **`uuid.js` —— 玩家身份**
   给每个玩家一个固定 ID（存在浏览器 Cookie 里），AI 的 ID 由你的 ID 派生。

8. **`handAnalyzer.js` —— 手牌提示**
   分析你手牌偏向，在界面显示一句提示（纯展示，不影响判定）。

## 四、一张牌从摸到和的完整流程

1. **开局**：`startNewRound()` 掷骰定庄 → 切牌（跳墩）→ 发牌 → 每家 13/14 张。
2. **摸牌**：`draw()` 从活牌山摸一张。
3. **判自摸**：`checkWin()` 看你手牌成没成形。
4. **出牌**：你点手牌 / AI 用 `getAIDiscardIndex()` 挑一张打。
5. **别人反应**：`afterDiscard()` 依次问 荣和 → 杠/碰 → 吃。
6. **和牌**：`declareWin()`（多家时 `declareMultiRon()`）算分、算赐马、写日志；庄赢连庄、庄输下庄。
7. **流局**：`flow()` 牌山空，显示各家手牌 + 听牌情况。
8. **存档**：每局结束 `saveSessionState()` 写到磁盘，下次能"接着打"。

## 六、几个容易混淆的点

- **"赋"不是"点"**：赋是役种计的小分，点是根据赋查表得到的大分（7赋=7000点…28赋=35000点封顶）。
- **"跳墩 / 岭上(马) / 王堆"不是一回事**：开局掷骰后，从切牌侧数出的 S 墩（2S 张）叫**跳墩**，整局不参与普通摸牌。跳墩里靠活牌山的 4 张是**岭上（马）**——开杠时从这里补摸、和牌时当"赐马"额外加赋；其余是**王堆**（死牌，不摸）。所以"牌山"（活牌山）= 136 − 跳墩，会随骰子大小变化（不再是固定 79）。
- **赐马 vs 岭上补摸**：开杠是从岭上**摸走**一张；赐马是**和牌后**把剩余岭上翻开、按"下一张"给胜者加赋。两者用的是同一堆牌，但时机与用途不同。
- **门风 vs 场风**：场风是"现在打到东南西北哪一圈"，门风是"你这把坐在哪个风位"——都影响役牌判定（且只算圈风与门风）。
- **tiisuin**：字牌七对子（`11223344556677z`）。已实现判定，**默认不计分**；门户开启"tiisuin算赋"后按 14 赋计，并累计到统计。
- **`handsPlayed` 和 `dealerCount` 是两个数**：前者每手都 +1（含连庄），后者只在庄家换人时 +1（用来算"东1局/东2局"）。

## 七、怎么跑起来

1. 双击 `run.cmd`（它会自己启动服务器 + 打开浏览器）。
2. 在门户选模式进入游戏。
3. 想测试：开 `debug.html` 改手牌/加速。
4. 想回看：看 `logs/` 目录。

> 改完任何代码，务必重新打开网页（刷新），并跑一局确认没坏。判断标准：能正常发牌、能出牌、能判和牌、不报错。
