### 补充：本轮自检中发现并修复的真实 bug

在做"文档改动后冒烟"时，发现 `index.html?mode=4` **渲染为空**（`#wallCount=0`、四座位无手牌），但**没有任何 JS 报错**，因此最初只检查"无报错"的断言会**误判为通过**。

- **根因**：上一版的启动兜底用 `setTimeout` 轮询（30×100ms）等待 `WinChecker`/`TiisuMahjong`，未就绪时**永久 `return` 放弃启动**；而在无头 `--virtual-time-budget`（虚拟时钟）下 `setTimeout` 会**瞬间触发**，实际没有等待网络，于是随机判定某个脚本"缺失"并中止。
- **同时**：`server.py` 原为单线程 `HTTPServer`，页面并发请求 8 个脚本 + 3 个 API 时会排队，加剧了脚本加载失败。
- **修复**：`index.html` 改为 `ensureDeps()`（`window.load` 后逐项检查、缺失则动态补加载、`<script onload>` 等真实网络、`?reboot=` 防缓存）；`server.py` 改用 `ThreadingHTTPServer`。
- **教训（已写入 `已知坑.md` 1.1 / 1.4 / 1.5、`AGENTS.md` 第五节）**：
  1. "无 JS 报错"**不等于**"页面正常"——必须同时断言渲染结果（如 14 张可点击手牌）。
  2. 对 `--dump-dom` 结果做子串计数前必须剥离 `<script>...</script>`，否则会把内联脚本模板源码当成已渲染 DOM。

## 二、自检方法

对 `docs/` 全部 `.md`/`.html` 及 `portal.html`/`debug.html`/`index.html` 运行检查脚本，做四类校验：

1. **链接存在性**：解析 `href`/`src`，按相对路径解析后判断文件是否存在。
2. **规则书锚点**：抽取全部 `id="secN"`/`id="toc"` 与 `href="#secN"`，比对是否一一对应。
3. **设置键一致性**：解析 `server.py` 的 `DEFAULT_SETTINGS`，与文档中提到的设置键比对。
4. **标识符存在性**：从文档中抽取 90 个关键函数/类名，检查是否在 `src/*.js` 或 `index.html` 中定义。

另附路径引用扫描（`docs/…`/`src/…` 等）。
