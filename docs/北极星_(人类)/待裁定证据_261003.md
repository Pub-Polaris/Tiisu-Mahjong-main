## 0. 先修了一个工具缺陷（影响本轮所有实测）

审核页输入框首版把 `tile.id` 拼成「数字在前」（如 `5z`），而引擎规范 id 是「**花色在前**」（如 `z5`）。
`_xyShape`（小于七/大于七）与 `isChidaichi`（全带赤）都是**按 id 比对**的，于是首轮实测把
小于七/大于七/全带赤**全判成不中**——那是输入框的 bug，不是引擎。

已修正：解析时生成规范 id `z5`/`m1`，渲染牌面时再转成文件名 `5z.svg`/`1m.svg`。
**以下均为修正后结果。**

## 1. E1 小于七 / 大于七 —— 字牌四对的组合限制（待裁定）

当前实现（`src/winchecker.js#_xyShape`）：字牌恰 8 张 = 4 对，且**三元（5z/6z/7z）占 1–3 对**，其余为风牌。

| 字牌四对构成 | 输入（暗手 14 张 + 和牌张） | 实测 |
|---|---|---|
| 3 三元 + 1 风 | `112233m 55z66z77z11z` 和3m | **小于七:14 + 混一色:5**（fu 19） |
| 1 三元 + 3 风 | `112233m 55z11z22z33z` 和3m | **小于七:14 + 混一色:5**（fu 19） |
| 2 三元 + 2 风 | `112233m 55z66z11z22z` 和3m | **小于七:14 + 混一色:5**（fu 19） |
| **0 三元 + 4 风** | `112233m 11z22z33z44z` 和3m | **不中** → 混一色:5+缺门:3+缺七:1+七对子:7（fu 16） |

- 若「必须含三元」→ 现状即正确。

## 2. E2 / E3 老少系 —— 根因是「可选役（默认关）」

`ike.json`：`同色老少`(1) / `同色双老少`(4) / `双色双老少`(2) / `双双逢`(2) / `三双逢`(4) 全部 `"optional": true`，
而 `checkWin` 对 `optional && !optionalEnabled` **直接跳过**（`src/winchecker.js:292`）。故默认永远不计。

| 形状 | 输入 | 实测 |
|---|---|---|
| 同色双老少（门清，天然七对形） | `123s123s789s789s55z` 和5z | 混一色:5+缺门:3+七对子:7（fu 15） |
| 同色双老少（**副露**，避开七对分支） | `chi:123s chi:789s` + 暗手 `123s789s55z` 和5z | 混一色:4+同高:4+二同高:7+缺门:4+混全带幺:4+单钓:2（fu 25）**同色双老少仍未计** |
| 两色双老少 | `123m789m123p789p55z` 和5z | 二色同顺:3+缺门:4+混全带幺:5+单钓:2（fu 14）**两色双老少未计** |

**关键结论**：即使**副露**（`meldCount>0`，根本不进七对分支），同色双老少也**不计**——
因为它是**可选役、默认关**。所以「是否要给同色双老少加非七对子前置」的**前提**是：
先定它到底**是不是常规役（默认开）**。

- 若改为常规役 + 默认开：**门清形**（`123s123s789s789s…`）仍会被 `seven_pairs` 分支截走，
  需像小于七那样**前置判定**；**副露形**可直接由 `conditionFn` 命中。
- 若保持可选：需要谁开谁显式 `optionalEnabled.add('same_color_double_old_young')`。

**问**：
1. 老少系 5 役保留「可选（默认关）」还是转为「常规役（默认开）」？
2. 若转常规：同色双老少的**门清七对形**是否也算（若是，需前置判定）？

## 3. E5 全带赤 —— 目录 #29 的形状是对的

`123m456m789m111p99s` 和9s → **一通:4 + 全带赤:14 + 单钓:2**（fu 20，特殊 16800）。

即交接文档 §三 A 的 #25「`123456789m +7z +1s5s7s9s` 凑不成 4 面子+1 对」是**那个牌串本身有误**；
正确的全带赤形就是形状目录 #29。全带赤**可达**。

## 4. §三 A 三个牌型的正形（已实跑）

| 项 | 交接文档原形 | 修正形（可成形） | 实测 |

`[ankan m1111]` 会同时命中 四归一（1m 共 4 张）——这是并计，非冲突。
