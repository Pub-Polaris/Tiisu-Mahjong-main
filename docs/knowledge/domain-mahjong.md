## 必须保真的口径（踩过坑）

1. **7 赋起和**；不足显示 `no_yaku` 属预期。
2. **听牌型奖赏在门槛之后叠加**：先判 `totalFu < baseFu` 直接返回，再算嵌张/边张/单钓/双碰/筋和。
3. **杠是「14 + 杠数」口径**：暗手长度 = `need*3 + 2`，1 杠全手 15 张、3 杠 17 张。
4. **七对形不构建 `groups`**：依赖 `groups` 的役在七对形下恒 false。
5. **可选役默认禁用**：7 个带 `optional: true`，验证台会全部启用，**探针/普通对局不会**。
6. **优先权链**：`ike.json` 的数组顺序即优先权（高役取第一个成立）；`notIf` 用于互斥前置。
7. **牌 id 方向**：引擎内部 `m1`/`z5`（花色在前）；文件名 `1m.svg`/`5z.svg`（数字在前）。

## 已知不可达 / 有意不设

- 不可达：`同色双老少`（同色两组 123 + 两组 789 + 雀头，每张牌都出现偶数次 → 整手必判为七对子，七对形不构建 groups）、`三七之花`（双役满，需特定 3/7 牌型 + 自摸）。
- ~~`三双逢` 不可达~~ **2026-10-18 更正**：那是判据写错导致的假象，已修为「3 花色、双数、相邻差 2 的刻子」，可达（断言与随机语料均覆盖）。
- 有意不设独立役：`一色二同高` / `一色四同刻`（按最大赋数归四暗刻）。
- 有意不补：`9.1/9.2 诈和与误报点数`（程序自动验算，前提不存在）。

## golden corpus（行为冻结）

- 生成器：`Web/scripts/gen_golden.py`（无头 Edge 打开 `scripts/yaku_test.html?golden=1`）。
- 原理：测试页在 `?golden=1` 时给 `checkWin` 包一层，记录**每次调用的输入与结果**；
  因此语料与现有 87 用例 / 202 断言**天然同步**，不需要单独维护一份用例。
- 产物：`NET/tests/fixtures/yaku-golden.json`（当前 102 条引擎调用，92 成功 / 10 失败）。
- 字段：`hand[] / melds[] / selfDraw / hasCalled / ankan / minkan / firstTurn / winTile / ctx`
  + `result{success, reason, totalFu, handType, yaku[], specialPoints, sevenHonors}`。
- 重新生成：改了 JS 判役后必须重跑，并把新 JSON 提交到 C# 仓库（它是 C# 的验收基准）。

## 高目优先（2026-10-18 北极星裁定）

同一手牌可能有多种「面子拆法」，**取赋数最高者**；赋数并列 → 役种数多者优先；仍并列 → 取先出现的。

- 实现：`WinChecker.maxSplit`（默认 `true`）。`checkWin` 在外层枚举 `splitStandardAll(hand)`，
  对每种拆法调用一次内部 `_checkOne`，按 (totalFu, 役种数) 取最优。
- 实证：`111222333m + 123p + 99p` 可拆成 3 刻（**18 赋**）或 3 顺（**29 赋**）→ 取 29。
- 七对 / 国士 / 九莲不参与枚举（唯一形状）。
- 关闭开关（`maxSplit=false`）可复现旧行为，用于对照。
